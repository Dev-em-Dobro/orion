# Guia rápido: como usar o modelo de contrato

Um contrato simples resolve 90% dos problemas com cliente: atraso de pagamento, "só mais uma coisinha" e desistência no meio. Use este modelo em todo projeto, mesmo os pequenos.

## Passo a passo

1. **Abra o `contrato-desenvolvimento.md`** (ou copie o texto pela página de entregáveis).
2. **Preencha tudo que está entre `[COLCHETES]`** com os dados reais: seus dados, os do cliente, valor, prazo e o Anexo I.
3. **Capriche no Anexo I.** É onde você define o que entra e o que fica de fora. Quanto mais claro, menos discussão depois.
4. **Ajuste os números se quiser:** dias de prazo, dias de aceite, valor-hora dos extras. Os padrões são só sugestão.
5. **Gere o PDF** (botão "Imprimir / Salvar PDF" na página) ou cole o texto no Google Docs / Word.
6. **Assine.** Pode ser assinatura física (duas vias) ou digital (Gov.br, Autentique, Docusign, Clicksign). Assinatura por app é válida.
7. **Cobre o sinal de 30% antes de começar.** Sinal pago = projeto começa. É o que separa cliente sério de curioso.

## Os 4 pontos que te protegem

- **Sinal de 30% na assinatura.** Você não trabalha de graça esperando "ver se dá certo".
- **60 dias de garantia (manutenção corretiva grátis).** Depois disso, correção é cobrada.
- **Fora do escopo é cobrado à parte.** Todo pedido novo passa por orçamento aprovado por escrito.
- **Aceite automático.** Se o cliente some depois da entrega, o prazo de revisão corre e o projeto é dado como aprovado.

## Dicas de ouro

- **"Aprovado por escrito" vale por mensagem.** Um "pode fazer, tá aprovado" no WhatsApp já serve de registro. Guarde as conversas.
- **Nunca comece sem o sinal.** É a regra que mais evita dor de cabeça.
- **Um projeto, um Anexo I.** Cada job tem seu escopo. Não reaproveite escopo antigo sem revisar.

> Este é um modelo de referência para projetos simples. Não substitui um advogado. Em projetos grandes ou valores altos, peça para um profissional revisar.
