# F019.1 — Ativação de acesso pós-login (Builders Club)

## Status
Implementada — 2026-07-27

## Objetivo
Após login, o aluno **vincula o e-mail da compra na Hubla** ao perfil Orion.
A verificação consulta `HublaEntitlement` (alimentada pelo webhook [F019](F019-webhook-hubla.md))
— **sem chamar API da Hubla**.

Depois da primeira verificação bem-sucedida, o cache no `User` evita consultas
repetidas; revogações do webhook invalidam o cache na próxima checagem.

## Pré-requisitos
- [F019](F019-webhook-hubla.md) — webhook + tabela `HublaEntitlement`
- `HUBLA_PRODUCT_ID` — filtra Builders Club (`VL3e0iDO3A32SyjJWr9S`)
- [F041](F041-webhook-tmb.md) — codes TMB Mentoria também liberam a mesma verificação de compra

## Modelo (campos no `User`)
| Campo | Tipo | Descrição |
|-------|------|-----------|
| `purchase_email` | string \| null | E-mail informado / da compra Hubla |
| `purchase_verified_at` | datetime \| null | Quando liberou; null = pendente |
| `purchase_product_id` | string \| null | Produto validado |

## Fluxo
1. Aluno faz login (Google ou magic link) — **sem bloquear** o envio do link.
2. Rotas do app principal seguem abertas para alunos logados.
3. Se `purchase_verified_at` ausente:
   - Tenta **auto-verificação** com o e-mail de login (`user.email`).
   - Se não achar entitlement → redireciona para `/ativar-acesso`.
4. Em `/ativar-acesso`, aluno informa **e-mail da compra na Hubla** e clica
   **Verificar compra** (relê só o banco local).
5. Entitlement `ativo` **e e-mail ainda não vinculado a outra conta** → grava
   cache no `User` → libera o app.
6. Entitlement ausente/revogado → mensagem amigável + link de compra (`HUBLA_CHECKOUT_URL`).

## Um e-mail de compra, uma conta (F036 — 2026-08-13)

Até 2026-08-03 nada impedia duas contas Orion de vincularem o **mesmo** e-mail
de compra: uma compra virava N acessos, bastando saber o e-mail de quem comprou.
O passo 5 passa a checar se existe **outro** `User` com o mesmo `purchaseEmail`
e `purchaseVerifiedAt` preenchido.

| Caminho | Se o e-mail já é de outra conta |
|---------|---------------------------------|
| Auto-verificação (e-mail de login, passo 3) | **pula em silêncio** e segue pros próximos candidatos; o aluno cai em `/ativar-acesso` como se não houvesse entitlement |
| Verificação manual (aluno digitou, passo 4) | `CompraJaVinculadaError` — *"Esse e-mail de compra já está vinculado a outra conta."* |

A assimetria é intencional: no automático o aluno não pediu nada, então não há o
que reportar; no manual ele pediu, e silêncio pareceria bug.

A regra vale pra vinculações **novas** — quem já estava vinculado antes não
perde acesso, e não há varredura retroativa. Duplicatas anteriores, se
existirem, continuam de pé até serem tratadas à mão.

**Onde isso não vale:** a exclusividade é do vínculo Orion, não da Hubla. O
mesmo e-mail continua podendo ter entitlement ativo em `HublaEntitlement` — o
que fica exclusivo é qual `User` o reivindica.

## Gate
- Exigência de compra verificada é aplicada **somente nos entregáveis** (`/entregaveis/*`), quando a feature de entregáveis estiver publicada.
- Orion principal (dashboard, leads, treino, configuração, conteúdo) permanece aberto para usuários logados.
- `/ativar-acesso` exige sessão, **não** exige compra.
- Webhook e páginas públicas (`/login`, `/termos`, `/privacidade`) fora do gate.

## Critérios de aceitação
- [ ] **AC1** — Usuário logado sem entitlement consegue usar o Orion principal normalmente.
- [ ] **AC2** — E-mail com entitlement `ativo` → `purchase_verified_at` preenchido e acesso liberado para entregáveis.
- [ ] **AC3** — E-mail sem entitlement → mensagem clara, sem erro 500.
- [ ] **AC4** — Entitlement revogado após verificação → perde acesso aos entregáveis na próxima requisição.
- [ ] **AC5** — E-mail de login = e-mail da compra → auto-verificação sem formulário.
- [ ] **AC6** — Gate de compra será aplicado apenas em `/entregaveis/*`.
- [x] **AC7** ([F036](F036-endurecimento-de-seguranca.md)) — E-mail de compra já
      verificado por outra conta: no manual vira mensagem amigável, no
      automático é pulado sem erro. Em nenhum dos dois a segunda conta é
      liberada.
